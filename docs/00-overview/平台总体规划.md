# DataPlat 平台总体规划

- 版本：v0.3
- 日期：2026-09-14
- 状态：草案
- 参考：阿里云 DataWorks（数据开发治理一体平台）
- 首期引擎：**Apache Doris**
- 执行身份：**Doris 个人账号**（平台用户 1:1 映射，查询/预览/问数执行均透传该身份）
- 问数模型：**公有云 API**（OpenAI 兼容协议）

## 1. 定位

DataPlat 是企业级数仓控制面：不替代 Doris，而是把集群上的数据变成可发现、可开发、可问答的资产。P0 三条线并行规划、同一工作空间与同一套权限：

1. **数据资产**：看见表、理解字段、追溯血缘（对标数据地图）
2. **SQL 开发**：在 Doris 上写、跑、存 SQL（对标 Data Studio / 临时查询）
3. **AI 问数**：用自然语言取数，SQL 可解释、可确认后再执行

## 2. 建设原则

1. **Doris 先行，模型可扩展**：元数据 URN、SQL Gateway、采集器按引擎插件设计，P1 再接 MySQL 等。
2. **资产是开发与问数的地基**：补全率、注释、类目、权限直接决定 NL2SQL 与补全质量。
3. **问数必须可审计**：只读、权限内表、展示 SQL、人确认执行；禁止静默写操作。
4. **即席与作业分离**：P0 把临时查询做稳；周期 DAG 放到 P1，避免首期铺太大。
5. **权限跟账号走**：不在 Gateway 上用空间代理账号跑 SQL；采集器可单独使用只读采集账号，与查询身份分离。
6. **问数走公有云**：密钥平台托管；出域内容仅限问题、检索到的表结构/注释/同义词及必要纠错信息，禁止上传未脱敏样例与全量结果。

## 3. 分期

| 阶段 | 目标 | 核心交付 |
|------|------|----------|
| P0 | 在 Doris 上找数、写数、问数 | 数据资产（Doris 采集）+ SQL 即席开发 + AI 问数 MVP |
| P1 | 把作业与质量管起来 | 调度编排、集成入仓、质量、跨源采集 |
| P2 | 口径与服务化 | 建模指标语义层、数据服务、安全中心 |
| P3 | 平台开放 | OpenAPI、联邦目录 |

```text
                    (FE MySQL 协议)
```
