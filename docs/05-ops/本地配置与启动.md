# 本地配置与启动

- 版本：v0.2
- 日期：2026-10-08
- 产品版本源：仓库根目录 `VERSION`

本文档是「一套可复现的本地一键体验」手册，覆盖三块内容：

1. **Doris 2FE + 2BE 集群**（业务数据源，含信贷测试库）——部署与运维
2. **平台基础设施** PostgreSQL / Redis（平台元数据）——启动
3. **API / Web 配置**（`DATAPLAT_*` 环境变量）——切换数据源到 Doris 的配置说明

> 集群级 YAML / 表结构 / 初始化 SQL 以 `deploy/` 下文件为准，本文档是操作手册。

---

## 1. 架构与端口总览

```text
浏览器 :5173 ──/api──► FastAPI :8000 ──┐
                                        ├─ PostgreSQL :5432   （平台元数据：workspaces/datasources/tables/columns）
                                        ├─ Redis     :6379   （缓存/会话）
                                        └─ Doris FE  :9030   （业务数据：SQL 工作台/AI 问数 真实执行目标）
                                                └── 2 BE 存储
```

| 组件 | 位置 | 端口 | 账号 |
|------|------|------|------|
| Doris FE master | `deploy/doris`（fe-1） | 8030(WebUI) / 9030(MySQL) | `root` / 空密码（Doris 2.0 默认） |
| Doris FE follower | `deploy/doris`（fe-2） | 8031 / 9031 | 同上 |
| Doris BE ×2 | `deploy/doris`（be-1/be-2） | 8041 / 8042 | —— |
| PostgreSQL | 根 `deploy/docker-compose.yml` | 5432 | `dataplat/dataplat` |
| Redis | 根 `deploy/docker-compose.yml` | 6379 | 无 |
| API | `apps/api` | 8000 | `admin/admin123`（本地骨架） |
| Web | `apps/web` | 5173 | 登录 `admin/admin123` |

## 2. 快速启动（一条命令串）

```bash
# 1) 平台基础：PostgreSQL + Redis
docker compose -f deploy/docker-compose.yml up -d

# 2) Doris 集群：2 FE + 2 BE（首次含 credit 信贷库初始化，等 1~3 分钟就绪）
cd deploy/doris && docker compose up -d && cd ../..

# 3) 健康检查：两个 BE 应 Alive=true
docker exec dataplat-doris-fe-1 mysql -uroot -P9030 -h127.0.0.1 -e "SHOW BACKENDS;"

# 4) API
cd apps/api
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements-dev.txt
python -m alembic upgrade head        # 平台元数据表（PostgreSQL）
uvicorn app.main:app --reload --port 8000

# 5) Web（另开终端）
cd apps/web && npm install && npm run dev
```

访问 **http://localhost:5173**，登录 `admin / admin123`。

### 2.1 Windows 一键脚本（可选）

仓库根目录的 `install.cmd` 可一键完成上述步骤（启依赖 → 启 Doris 并**等待 BE 就绪** → 装依赖/迁移 → 打印 API 与 Web 启动命令），双击或命令行执行：

```cmd
install.cmd
```

脚本行为说明：

- **只准备、不常驻**：脚本会把 PostgreSQL/Redis、Doris 集群、Python 依赖、数据库迁移全部准备好，但 API（uvicorn）与 Web（vite dev）需要常驻终端，故脚本最后**打印启动命令**，按提示开两个终端执行即可（见脚本末尾输出）。
- **BE 就绪等待**：脚本会轮询 `SHOW BACKENDS` 直至 BE 全部 `Alive`（超时约 6 分钟），避免 API 起来时 Doris 还没就绪。
- 各步骤的具体命令与排查仍以本文档与下方各节为准。

## 3. Doris 集群部署与运维

详细内容见 [`deploy/doris/README.md`](../../deploy/doris/README.md)。要点：

- **编排文件**：`deploy/doris/docker-compose.yml` —— 2 FE（master/follower）+ 2 BE，每实例 `mem_limit: 5g`，固定内网 IP（FE 10.0.80.2/3，BE 10.0.80.4/5），本地目录持久化。
- **镜像**：因本机无法直连 Docker Hub，使用加速镜像 `docker.1panel.live/apache/doris:2.0.0_alpha-*`；网络 OK 时可改回官方 `apache/doris:*`。
- **首次启动注意（Windows / Docker Desktop）**：Doris BE 要求内核参数 `vm.max_map_count >= 2000000`，而 Docker Desktop（WSL2）默认 `262144`，不满足时 BE 进程起不来（表现为 `Connection refused`、`SHOW BACKENDS` 一直 `false`）。本机已执行：
  ```bash
  wsl -d docker-desktop -u root -- sysctl -w vm.max_map_count=2000000
  ```
  **重启 Docker Desktop 后该参数会重置**，需重新执行。建议：
  - 每次启动前检查：`wsl -d docker-desktop -u root -- sysctl vm.max_map_count`
  - 或写入 Docker Desktop 的 WSL 启动脚本，令其常驻（如 `/etc/wsl.conf` 结合 docker-desktop 的启动钩子）。
- **重置集群**：`cd deploy/doris && docker compose down -v && rm -rf fe-* be-* && docker compose up -d`
- **重灌信贷数据**：`/docker-entrypoint-initdb.d` 只在 BE 首次启动时执行一次；重置后自动重灌，或手动执行 `deploy/doris/init-sql/001_credit.sql`。

## 4. 信贷测试库（credit）

初始化脚本：`deploy/doris/init-sql/001_credit.sql`（BE 首次启动自动执行；本次已手工重灌并验证）。

| 表 | 模型 | 说明 |
|----|------|------|
| `customer` | Unique | 客户维度（征信分、状态） |
| `account` | Unique | 账户维度 |
| `loan_contract` | Unique | 贷款合同事实（金额/余额/利率/逾期） |
| `repay_record` | Unique | 还款流水事实 |
| `overdue_record` | Unique | 逾期事实 |
| `loan_summary_daily` | Aggregate | 按日产品汇总指标 |

验证：

```bash
docker exec dataplat-doris-fe-1 mysql -uroot -P9030 -h127.0.0.1 -e "USE credit; SHOW TABLES; SELECT COUNT(*) FROM customer;"
```

演示查询：

```sql
-- 贷款按状态分布
SELECT status, COUNT(*) cnt, SUM(loan_amount) amt FROM credit.loan_contract GROUP BY status;
-- 逾期客户 TOP
SELECT c.customer_name, l.contract_no, l.overdue_days, l.loan_balance
FROM credit.loan_contract l JOIN credit.customer c ON l.customer_id = c.customer_id
WHERE l.status = 'OVERDUE' ORDER BY l.overdue_days DESC;
```

## 5. 项目配置（数据源切换说明）

平台按架构约定：**PostgreSQL 存平台自身元数据，Doris 承载业务数据**（SQL 工作台 / AI 问数 / 采集目标）。平台元数据库始终指向 PostgreSQL，不对 Doris。

### 5.1 后端配置项

配置集中在 `apps/api/app/core/config.py`（`DATAPLAT_` 前缀环境变量覆盖），模板见 `deploy/env/api.env.example`：

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `DATAPLAT_DATABASE_URL` | `postgresql+psycopg://dataplat:dataplat@127.0.0.1:5432/dataplat` | 平台元数据库（PostgreSQL，保持不变） |
| `DATAPLAT_REDIS_URL` | `redis://127.0.0.1:6379/0` | 缓存 / 会话 |
| `DATAPLAT_DORIS_HOST` | `127.0.0.1` | Doris FE 地址 |
| `DATAPLAT_DORIS_PORT` | `9030` | Doris FE MySQL 协议端口 |
| `DATAPLAT_DORIS_USER` | `root` | 查询账号 |
| `DATAPLAT_DORIS_PASSWORD` | 空 | Doris 2.0 root 默认空密码 |
| `DATAPLAT_DORIS_DATABASE` | `credit` | 默认库 |
| `DATAPLAT_DORIS_CONNECT_TIMEOUT` | `10` | 连接超时（秒） |
| `DATAPLAT_DORIS_COLLECTOR_USER/PASSWORD` | 空 | 元数据采集专用只读账号（预留） |
| `DATAPLAT_ADMIN_USER/PASSWORD` | `admin/admin123` | 本地骨架登录账号 |

### 5.2 SQL 网关已真实执行

`apps/api/app/modules/sql/service.py`：`/api/v1/sql/preview` 先过只读护栏（`guard.py`，仅 SELECT/SHOW/EXPLAIN/DESC），再用 PyMySQL 连接 Doris FE 执行并返回 `{columns, rows, row_count, truncated}`。Web「SQL 开发」页改为结果表格展示。

> 当前使用平台侧统一 `DATAPLAT_DORIS_*` 账号执行；后续接入「个人 Doris 账号绑定」后应按用户切换连接身份（见架构文档 §7 安全边界）。

## 6. 常见问题排查

| 症状 | 处理 |
|------|------|
| `SHOW BACKENDS` 全为 `false` / `Connection refused` | 检查 `vm.max_map_count`（见 §3）；`cd deploy/doris && docker compose restart be-1 be-2` |
| 初始化 SQL 报 `Disable to create table with DATE` | Doris 2.0 用 `DATEV2`（init SQL 已处理） |
| 初始化 SQL 报 `AGG_KEYS table should specify aggregate type` | Aggregate 模型非 Key 列需显式聚合类型（`SUM`），init SQL 已处理 |
| `INSERT ... strict mode` 报列超长 | 列宽不足（如 repay_method），init SQL 已把 `VARCHAR(16)`→`VARCHAR(32)` |
| API 报 `无法连接 Doris` | 确认集群已 up、`DATAPLAT_DORIS_PORT` 是否对应 FE 查询端口 |
| 浏览器打不开 Web | Vite 默认绑 `::1`，用 `http://localhost:5173`（勿用 `127.0.0.1`） |
