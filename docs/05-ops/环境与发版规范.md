# 开发、测试与 Release 规范

- 版本：v0.1
- 日期：2026-09-14
- 产品版本源：仓库根目录 `VERSION`

## 1. 环境

| 环境 | 用途 | 分支 / 制品 | 数据 |
|------|------|-------------|------|
| local | 开发者本机 | 任意 feature | Compose 起 PG/Redis；Doris 连开发集群 |
| dev | 持续集成环境 | `develop` 自动部署 | 共享 Doris 开发库，可重置 |
| test | 提测 / 回归 | `release/*` 或 `vX.Y.Z-rc.N` | 脱敏后的准生产数据 |
| prod | 生产 | `main` + 标签 `vX.Y.Z` | 生产 Doris，个人账号真实权限 |

环境变量：`DATAPLAT_`（后端）、`VITE_`（前端构建期）。禁止提交 `.env`。

## 2. 版本号

遵循 SemVer：`MAJOR.MINOR.PATCH[-prerelease]`。

| 产品阶段 | 版本示例 | 含义 |
|----------|----------|------|
| P0 开发中 | `0.1.0-dev` | 当前默认，不可当生产 |
| P0 提测 | `0.1.0-rc.1` | 测试环境发布 |
| P0 首发 | `0.1.0` | 生产 Release |
| P0 缺陷修复 | `0.1.1` | 补丁 |
| P1（调度/质量） | `0.2.0` | 次版本 |
| 对外稳定后不兼容变更 | `1.0.0` | 主版本 |

- `VERSION`、`apps/web/package.json` 的 `version`、API 启动 banner 必须一致。
- Git 标签：`v0.1.0`、`v0.1.0-rc.1`。
- GitHub Release 绑定标签。
- `0.x` 允许 API 破坏性变更，必须写入 `CHANGELOG.md`。

## 3. 分支

```text
feature/*  ──PR──► develop ──release/* ──PR──► main
                       │                      │
                       └── 日常 dev 部署        └── tag vX.Y.Z → prod
hotfix/* ──────────────────────────────PR──► main 并回合并 develop
```

P0 人少时可暂用 GitHub Flow（`feature` → `main`），仍用标签区分 rc / 正式版。

## 4. 本地开发

前置：Node 18+、Python 3.10、Docker、可连通的 Doris FE。

```bash
docker compose -f deploy/docker-compose.yml up -d postgres redis

cd apps/api
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000

cd apps/web
npm install
npm run dev
```

前端将 `/api` 代理到 `http://127.0.0.1:8000`。OpenAPI：`http://127.0.0.1:8000/docs`。

## 5. 测试分层

| 层级 | 工具 | 门禁 |
|------|------|------|
| 前端单测 | Vitest | PR CI（有用例即跑） |
| 前端 E2E | Playwright（P0 后半段） | test 环境 |
| API 单测 | pytest | PR 必过 |
| 护栏测 | 禁 DROP、无权限表不进 Prompt | PR 必过 |
| 问数金标 | 20～50 条业务问句 | rc 发布清单 |

## 6. Release 流程

1. 冻结 `develop`，拉 `release/x.y.z`。
2. `VERSION` 改为 `x.y.z-rc.N`，打标签，部署 test。
3. 测试签出。
4. `VERSION` 改为 `x.y.z`，合入 `main`。
5. 打 `vx.y.z`，写 GitHub Release。
6. 部署 prod 并冒烟（健康检查、绑定账号、SELECT、问数）。
7. `main` 回合并 `develop`。

## 7. CI

`.github/workflows/ci.yml`：PR / push 跑前端 build 与后端 pytest。生产密钥只放部署环境，CI 使用 mock。
